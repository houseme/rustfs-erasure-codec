# Classic inverse-cache hash follow-up

This change moves erasure-key hashing outside the Classic cache mutex and
reuses that hash for lookup, replacement removal and insertion. Mutable LRU
state and its byte accounting share one guard. Successful lookups return a
shared decode handle and advance recency.

The hash builder is cloned into the LRU at construction. Hashing borrowed
indices therefore agrees with the stored Vec key. Full slice equality handles
collisions. Codec clones construct independent cache state. Inverse arithmetic
runs after a miss has released the guard.

## Investigation and measurements

The initial host matrix completed all 32 workloads. It showed several improved
concurrent warm cases and a +6.86% wall median for serial 64+4, 64-byte cold
recovery. The next candidate added inline hints to its small hash and lookup
methods, then received independent six-round runs and same-instance controls.
The host screen's compiler-hint variant is retained as a patch.

The final Docker Linux ARM64 run used one pinned CPU for serial work, two for
eight callers, and a two-CPU quota. It completed 24 ABBA/BAAB rounds for each of
32 workloads. Every drift flag remains in the raw record. A separate six-round,
500-millisecond follow-up targeted the flagged 64+4 cold case.

## Correctness coverage

- Weighted cache tests exercise LRU eviction, oversized rejection, same-key
  replacement, key capacity and workspace ownership after eviction.
- New tests force colliding hashes, empty keys and zero retention limits.
- A thread computes a key hash while another thread holds the cache-state
  guard, proving the lookup hash's lock independence.
- Eight workers exercise prehashed replacement and memory snapshots. The final
  charged total is compared with the sum of retained entry charges.
- Generic Field, no_std, compact/dense recovery and public reconstruction
  entry points pass their existing regression suites.

Observer generation accepts the current prehashed lookup and the historical
lookup bodies. Its negative tests reject unknown or ambiguous boundaries.
Review of generated bytes found the expected reconstruction-source change.

## Reproduction

Build the baseline and candidate with `std simd-accel`, distinct rustc metadata
and a shared target directory. Link the copied rlibs and matching libc rlib as
shown in the existing diagnostic instructions.
[Build instructions](gf16-plan-cache-followup-2026-11-13.md#reproduction)

```sh
RSE_CACHE_FAMILY=classic \
RSE_CACHE_ROUNDS=24 \
RSE_CACHE_SAMPLE_MS=20 \
RSE_CACHE_PHASE_WARM_MS=0 \
RSE_CACHE_PIN_CPUS=0,1 \
RSE_CACHE_FILTER=classic/concurrent/ \
./paired-probe > classic-concurrent.jsonl
```

Classic selects layouts 10+4, 64+4, 128+4 and 240+4 with a 16-entry cache.
Its rotating workload contains 20 erasure patterns. `RSE_CACHE_SAME_CODEC=1`
selects the same codec instance for both timing roles.
