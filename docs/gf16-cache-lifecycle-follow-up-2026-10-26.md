# GF16 缓存生命周期与并发内存取舍

接续 [verify 资源矩阵](verify-workload-follow-up-2026-10-26.md)，本轮推进全局复审
执行顺序第 5 项的测量前置条件。结论是继续保留现有运行时策略：oversized decode

## 可复用的生命周期实验

新增 `tests/leopard_cache_lifecycle.rs`，沿真实公共 reconstruct 路径执行：

- LeopardGF16，64 KiB 字节分片，缺失并恢复第 0 个 data shard。
- 小配置 10+4：16 个 FFT work lane 加一个转换/scaling scratch，共 1,114,112 B。
- 超限配置 40+16：64 个 work lane 加一个 scratch，共 4,259,840 B，超过 4 MiB
  的可变 workspace 缓存上限。两项均另有 64 KiB 临时输出，恢复后发布到原有 ShardSlot。
- 1、2、4 个独立调用线程，每个 codec 的 max_parallel_jobs=1；这测的是多个并发调用，
  不是一次调用内部 Rayon 的调度或吞吐。
- 两个不可变解码计划在单独线程预热后 join，释放它的可变 TLS；每个测量 worker
  再预热自己的小配置。输入、codec、输出 backing storage 及预热均在计数窗口外。
- 每组顺序为小命中、超限、小恢复、小命中、再次超限、连续超限、再次小恢复。
  每个线程数使用三组新 worker，共 63 个窗口/策略。

所有窗口逐字节核对全部分片、present 状态及缺失输出的原有地址。worker 捕获恢复
异常后仍完成同步，由父线程统一判失败，避免在阶段屏障留下等待者。

```bash
cargo +stable test --release --locked -p rustfs-erasure-codec --features simd-accel \
  --test leopard_cache_lifecycle -- --nocapture
```

计数器从进程开始持续跟踪成功分配的 requested live bytes，因此能识别“窗口前分配、
窗口内释放”的缓存。另计窗口内申请次数与申请量，重分配按成功后的净长度调整 live，
按完整目标大小统计申请量。自检覆盖窗口前分配、zeroed、增长/缩短 realloc、释放、
负的存活增量和峰值，均有精确数值断言。

每个阶段由 start/done/release 三个屏障界定。父线程读取窗口结束值后才释放 worker，
防止线程退出或输入析构混入结果。申请计数覆盖所有 Rust allocator 线程，包含同步
元数据；首个小命中窗口另有 224 B 申请/存活增量，未精确归因或扣除。其余小命中
窗口只申请临时输出。测试保留小额元数据容差，不断言依赖线程重叠程度的固定峰值。

这里的峰值是观察到的“净存活申请字节”，包含基线中的 fixtures、缓存和运行时状态。
它不包含 allocator rounding、allocator 内部元数据、realloc 实现内部的瞬时并存、
绕过 Rust global allocator 的分配、栈或静态 TLS，不等同于 RSS。屏障只同步开始，
未强制所有计算在任意时刻完全重叠，不能据此给出生产最坏峰值或速度结论。

## 临时替代策略及结果

从上述提交归档到临时目录，只改变 std 路径在不可缓存尺寸下的资源取得方式：
保留 TLS 中的小 workspace，另建本次超限调用的局部 workspace。
[完整实验补丁](../benchmarks/global-review/2026-10-26/gf16-cache-preserve-experiment.patch)
同时明确替代实验的缓存/申请预期；没有增加运行时开关，没有应用到正式分支源码。
两份探针仍保留完整数据、指针、计数目录、申请预算及峰值自洽检查。

以下结果在三次重复中一致；申请量包含临时输出及实际元数据：

| 每阶段调用线程 | 超限后的小请求：现有策略申请 | 保留策略申请 | 保留策略在超限后多持有的小缓存 |
| --- | ---: | ---: | ---: |
| 1 | 1,179,648 B / 3 次 | 65,536 B / 1 次 | 1,114,112 B |
| 2 | 2,359,296 B / 6 次 | 131,072 B / 2 次 | 2,228,224 B |
| 4 | 4,718,592 B / 12 次 | 262,144 B / 4 次 | 4,456,448 B |

超限调用自身两种策略申请相同：每 worker 7 次、4,328,696 B。
首次超限时，现有策略释放小缓存；替代策略保留它。在本次观察中，替代策略相对阶段
开始的峰值增量分别多 1,114,112 / 2,228,224 / 4,456,448 B。完整 live_before、
live_peak、live_after 及连续超限情况均保留，不能只比较某个窗口的峰值增量而忽略
其已经持有的小缓存。此处是受控负载，不是生产分布，也不是普遍的峰值上限。

还对临时替代源码运行既有单测
`decode_workspace_retention_counts_all_buffers_and_drops_oversized_entries`，实际以 101
退出，在 `cache.borrow().is_none()` 断言失败。这是预期的策略契约负向对照，不是正式
分支回归失败；替代实验没有通过完整发布门禁，不能标记为可直接采用的候选实现。
