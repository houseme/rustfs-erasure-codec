## 实现

原数据阶段每块构造存活输入和可变输出两张 `SmallVec<[...; 32]>`。
输入数或缺失数据数超过内联容量后，申请次数随块数增长。

现在执行器通过私有、静态分发的输入适配器，按计划中的存活索引读取分片，与连续输入共用
原有算术、分块和内核选择。缺失数据的 Vec 所有权暂时移到一个跨块复用的容器中，
让输入和输出处于互不重叠的所有者集合；计算后按原目标顺序放回原槽位，
再进入 parity 阶段、I/O 和探针边界。

移动的是 Vec 的指针、长度和容量元数据，没有复制 payload。容器每块 drain 后为空，
容量保留到 API 返回；宽布局只在调用内准备一次容器，不跨块保存可变引用。
没有新增公共 API、unsafe、生命周期转换、全局缓存或经验性尺寸阈值。

连续输入仍直接传给原 GFNI 入口。索引输入只有满足既有原生条件时才准备最多 32 个
内联引用；输出仍使用原来的最多 4 个内联原生适配引用。更宽布局按索引进入共享循环，
没有为了删表绕过原生选择或重新实现算术。内联和容器存储仍存在，未测量 stack/RSS。

## 冷规划资源对照

[完整记录与源码绑定](../benchmarks/global-review/2026-10-26/data-owner-resources.json)
保留每版本 9 条配对记录、18 个计数窗口。外部回归源码在两次测量中逐字节一致，
基线断言先实际失败，候选通过。每个布局重复三次，均恢复出完整正确输出。

关闭逆矩阵缓存，计入每次调用的冷矩阵准备。块大小 1024 B，分片长度分别为
1061/5157 B，即 2/6 个块，均包含 37 B 短尾。Reader 数据及 Writer 容量在计数前准备，
API 内部 payload 缓冲、计划、矩阵和元数据申请保持在窗口内。计数覆盖调用线程的
alloc/alloc_zeroed/realloc 请求；I/O 与计算均串行，不把其他线程的申请遗漏为零。

| 布局 / 缺失目标 | 2 块申请次数，前 → 后 | 6 块申请次数，前 → 后 |
| --- | ---: | ---: |
| 33+34 / 1 data | 73 → 71 | 77 → 71 |
| 33+34 / 33 data | 79 → 76 | 87 → 76 |
| 40+40 / 33 data + 2 parity，带间隔目标 | 92 → 89 | 100 → 89 |

跨块申请增长已消除。整个 API 仍会申请缓冲和规划存储，不能把这个结果写成整个 API
零分配；也不能把总申请次数减少等同于吞吐改善或峰值 RSS 下降。本轮没有重新计时。

## 功能与工具验证

新增功能场景覆盖首/尾/间隔数据目标、1～6 个缺失数据、混合 parity 缺失、
Vandermonde/Cauchy/JerasureLike、Auto/Serial/Parallel I/O、多块和短尾。
宽布局截断回归确保仅已完成块被写出；非法的当前块不发布，缺失 Cursor 位置保持。
现有自定义矩阵、奇异规划、全部小布局、部分 I/O 和错误回归一起通过。

探针生成器识别新旧两种已知调用形式，拒绝缺失或歧义锚点，继续严格校验生成字节。
新旧源码都实际注入并编译：当前副本 43 项相关回归通过，旧副本 19 项通过。
payload 所有者在每个观测边界已放回原槽位；这些检查不构成正式生命周期采集或发布验收。
