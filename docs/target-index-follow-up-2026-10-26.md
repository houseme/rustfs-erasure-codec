## 让完整请求复用已有所有者

普通完整恢复直接使用 ClassicReconstructShape 拥有的有序缺失索引。此前 required
入口总会过滤并复制一份目标，即使 mask 恰好请求了每个缺失分片。超过内联 64 项时，
这份完全相同的目标列表还会产生堆申请，并在 workspace 中随计划保留。

共享 planner 现在查找第一个未请求的缺失索引。没有排除项时，沿用 shape 自己的
有序索引；出现排除项时才建立子集列表，把此前已接受的前缀复制一次，再过滤余下
后缀。每个相关 required 标记只读取一次，结果依然是 data 目标在前、parity 在后。

两个表示都由计划拥有，不借用 required mask，也没有新增外部生命周期约束。
调用者修改或释放 mask 后，准备好的 workspace 仍保持原目标。短 data mask、空请求、
未请求 missing data 对组合 parity 的贡献和奇异矩阵处理继续沿用既有规则。

本轮修改同一个目标选择位置，供普通、优化及 workspace 入口复用。shape/长度扫描、
复用布局校验、逆矩阵与缓存、parity 系数组合、执行器和并行策略均保持原实现。
没有增加 API、runtime 开关、unsafe 或缓存。本轮唯一运行时源码变化是 recovery_plan.rs；
另一个 src 变更是其私有测试模块，其他源码、manifest、lockfile 和 build 脚本逐字节相同。

## 准备与普通调用分别计数

[完整资源记录与源码绑定](../benchmarks/global-review/2026-10-26/target-index-resources.json)
包含前后版本、指标开/关四个 release 构建的完整记录：每构建两字段、12 布局、三次
重复，共 72 条；每条记录同时计数四个 API 窗口，共 1,152 个窗口。

四个窗口分别为 prepare_reconstruct_workspace、prepare_reconstruct_some_workspace、
普通 reconstruct、普通 reconstruct_some。后两者包含当次计划构造与恢复执行。
输入使用预先分配的 ShardSlot，65 元素分片，Classic/Cauchy、逆矩阵缓存开启。
required 只在缺失索引处为 true；本目录只有 data 或只有 parity 缺失，确保配对的
完整目标与 required 目标使用同样的系数，不混入混合恢复的组合行表示差异。

codec、参考编码、容器和 mask 均在计数外准备，两种普通调用预热后再采集。
准备返回的两份计划也会在计数外执行，核对目标及全部输出；每次普通调用同样核对
全部恢复字节。计划销毁在准备计数窗口外。计数覆盖调用线程的 alloc/alloc_zeroed/
realloc 请求，realloc 按完整新目标大小计入，不代表 RSS 或存活峰值。
